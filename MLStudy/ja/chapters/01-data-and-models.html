01 / 予測時点を決める

架空の自転車貸出所で次の1時間の貸出数を予測するとします。モデルを選ぶ前に「いつ、何を知っているか」を決めます。午前8時には9時の実際の天候や次の1時間の返却数はまだ分かりません。訓練データに値があるというだけで入力すると未来の情報が混入します。

この資料は実運用データを使いません。小さな合成例でデータ表現、学習、検証の構造を調べます。実験結果は合成条件下の観察であり、実サービスの性能として解釈しません。

この章の目標

標本と特徴の軸、パラメータとハイパーパラメータを区別します。予測時点で利用可能な入力だけを使って評価を計画します。

02 / 観測をベクトルに

一つの観測をベクトルxにまとめ、複数の観測を行列Xの行に並べます。標本数N、特徴数Dに対しXはN × D行列です。目標値yは各行に対応し、行の順番を変えるときは目標値の順番も変えます。

重要な式x = [気温, 予報降水確率, 利用可能な自転車数]T
X ∈ ℝN×D,   y ∈ ℝN
予測時点 気温 (°C) 降水確率 利用可能台数 その後の貸出数
08:00 18 0.2 24 11
09:00 20 0.1 17 14
10:00 22 0.1 12 10

数値で保存しても距離に意味があるとは限りません。貸出所番号1と2が1と9より似ているとは言えません。カテゴリ変数にはワンホット符号化などの表現が必要です。時刻は周期的なので、深夜0時の前後が近くなるよう二つの座標で表すこともできます。

周期的な時刻表現h ↦ [sin(2πh/24), cos(2πh/24)]

03 / モデルは仮定を含む関数

モデルは入力を出力に変換する関数です。線形モデルは特徴の寄与を足し合わせると仮定します。確率モデルは同じ入力でも出力が変わる不確実性も表します。どちらも現実を完全には表せません。

重要な式ŷ = fθ(x)、または p(y | x, θ)

θはデータから推定するパラメータです。多項式の次数、学習率、正則化の強さは学習過程を定めるハイパーパラメータです。学習とは、決められた関数族の中で目的関数を基準にパラメータを選ぶ過程です。

学習形態 与えられる情報 問い
教師あり学習 入力と目標値 貸出数はいくつか？どのカテゴリか？
教師なし学習 主に入力の観測 どのような構造、分布、圧縮表現があるか？
強化学習 行動後の状態と報酬 長期報酬を高める行動は何か？

次元削減とクラスタリングは教師なし学習の代表例です。このサイトの実験は教師あり・教師なし学習に集中します。強化学習には環境と逐次意思決定が加わるため、ここでは概要だけを扱います。

04 / 良い予測の基準を作る

損失は正解と予測の差を数値化します。回帰の二乗誤差は大きな残差を強く反映し、絶対誤差は残差の大きさに線形に反応します。損失は誤りの費用に応じて選びます。

重要な式MSE = (1/N) Σi (yi − ŷi)²
MAE = (1/N) Σi |yi − ŷi|

残差が[1, −2, 3]ならMSEは14/3、MAEは2です。MSEの単位は目標値の単位の二乗で、RMSEは元の単位に戻ります。分類では正解率だけだと少数クラスの失敗を隠すため、混同行列も確認します。

比較の出発点

訓練目標値の平均を常に予測する基準モデルを用意します。複雑なモデルと単純な基準を同じ評価データで比較します。

05 / 学習と評価の間に境界を置く

訓練データで係数を求め、検証データで設定を選び、選択後に別のテストデータで最終性能を確認します。テスト結果を見て修正を繰り返すと、テストも実質的に検証データになります。

貸出数のように時間順が重要なら過去で学習し、その後の期間で検証します。無作為分割は未来のパターンを過去の予測に漏らす場合があります。平均、標準偏差、欠損補完値も訓練期間だけで計算します。独立標本では交差検証で分割間の性能変動を確認できます。 

import numpy as np
X = np.array([[18,.2,24],[20,.1,17],[22,.1,12],
              [17,.6,30],[16,.8,28],[19,.3,21]], dtype=float)
y = np.array([11,14,10,6,4,9], dtype=float)
cut = 4  # 説明用の時間分割法です。実際の性能評価には、サンプルが不足しています。
mu, scale = X[:cut].mean(0), X[:cut].std(0)
scale[scale == 0] = 1
X_valid = (X[cut:] - mu) / scale
baseline = np.full(len(y[cut:]), y[:cut].mean())
print("validation MSE:", np.mean((y[cut:] - baseline)**2))
実験室での評価の呼び方

スライダーで繰り返し比較する値は検証誤差です。最終サービス性能やテスト性能とは呼びません。

06 / 理解を確認する

標本数が特徴数より多ければ必ず良いモデルか？

いいえ。標本の多様性、入力情報、漏洩、分布変化、モデルの仮定も重要です。標本数だけでは汎化性能を保証できません。

全データを標準化してから分割してよいか？

評価のための分割では、訓練部分から平均と標準偏差を推定します。全データには評価部分の分布情報が含まれます。

学習のまとめ： モデル選択の前に観測単位、予測時点、評価基準を定めます。次章では損失を最小化する線形モデルを計算します。

発展A / 時間特徴を設計し未来を評価する

発展A · 特徴設計と分布変化

考える問題 時刻をそのまま数値化したモデルと周期特徴を使うモデルを比較します。過去をよく説明するモデルは次の時間帯でも有効でしょうか？

架空の装置の時間別要求量を200個作ります。t=0,…,199、h=t mod 24、y=30+8sin(2πh/24)+6·1[t≥140]+ε、ε~N(0,1.5²)です。要求量は連続近似で丸めません。NumPyシード2101を使い、訓練0〜119、検証120〜159、テスト160〜199に固定します。

重要な式φ(h) = [1, sin(2πh/24), cos(2πh/24)]
θ̂ = argminθ ‖ytrain − Φtrainθ‖²
  1. 線形時間特徴[1,h]は23時と0時を遠くに置きます。sinとcosの二座標は一日を円上に置き、深夜0時の両側も隣同士に表します。
  2. 両モデルとも訓練120件だけで最小二乗を解きます。検証期間を見て係数を再調整しません。
  3. 検証MSEは生の時刻特徴35.405から周期特徴20.596へ下がります。改善しても生成ノイズ分散2.25より大幅に大きい値です。
  4. t=140で平均が6移動します。周期モデルもこの変化を学べず、テストMSEは34.592です。表現の改善と分布変化への対応は別の問題です。
特徴に傾向tを加えれば自動的に解決するか？

訓練中に急な水準変化がないため、単純な傾向追加だけでは未来の跳躍を知ることはできません。再学習規則、変化検知指標、検知後の性能を別の時間期間で評価する必要があります。

発展B / 良すぎる結果から漏洩を探す

発展B · 誤った性能診断

考える問題 MSEが0.001未満のモデルができました。優秀なのか、それとも予測時点で分からない情報が入っているのでしょうか？

同じ標本で三つの誤りを区別します。時間期間を混ぜる評価、テストを見てモデルを選ぶ評価、正解の一部を特徴に入れる評価です。最後を再現するため、要求終了後の集計値z=y+δ、δ~N(0,0.02²)を作ります。この特徴は予測時点には存在しません。

  1. 予測時点を基準に正しい入力一覧を作ります。過去の集計は使えますが、まだ終了していない要求の事後集計は使えません。
  2. 最初の160件を混ぜて120/40に分けると周期モデルの検証MSEは3.494です。時間順の20.596とは分布移動の難しさが変わっています。観測が異なるため、純粋なモデル改善の比較ではありません。
  3. 訓練特徴にzを加えると未来の検証MSEも0.000496まで下がります。しかし検証特徴自体に正解が含まれるため、有効な予測性能ではありません。
  4. 平均、標準偏差、欠損補完、特徴選択も訓練観測だけで決めます。検証には決めた変換を適用し、最終テストは選択後に一度確認します。
計算コードの要点を開く

発展Pythonの対応する関数から計算の流れを抜粋しています。完全なデータ生成と補助関数は以下のダウンロードにあります。

train = np.arange(120)
valid = np.arange(120, 160)
mu, sd = X[train].mean(0), X[train].std(0)
sd = np.where(sd == 0, 1, sd)  # 上界特性処理
Z_train = (X[train] - mu) / sd
Z_valid = (X[valid] - mu) / sd
# 禁止されている比較の入力：z = y + noise
# 正解を含む特徴は、上記の変換によっても解決されない。
先に訓練と検証を分け、それぞれ正解由来の特徴を作れば安全か？

いいえ。行が重複していなくても予測時点で未知の正解を入力すれば目標漏洩です。行の分離と特徴の時間的な利用可能性を両方確認します。

発展C / 正解率ではなく費用で閾値を選ぶ

発展C · 不均衡分類と費用

考える問題 故障率2%の装置で正解率の高い閾値を選べば、見逃す故障も減るでしょうか？

別の合成検証観測10,000件を故障200件、正常9,800件に分けます。スコアはs=2y+ε、y∈{0,1}、ε~N(0,1)です。s≥τで警報を出します。sは確率ではなく、閾値0.5に特別な確率的意味はありません。故障見逃し(FN)の費用25、誤警報(FP)の費用1と仮定します。

重要な式Precision = TP/(TP+FP),   Recall = TP/(TP+FN)
Cost(τ) = 25·FN(τ) + FP(τ)
τ TP / FP / FN 正解率 適合率 / 再現率 総費用
0.5 191 / 3003 / 9 69.9% 6.0% / 95.5% 3228
1.5 133 / 676 / 67 92.6% 16.4% / 66.5% 2351
2.5 51 / 63 / 149 97.9% 44.7% / 25.5% 3788
  1. すべて正常と予測すると正解率98%、故障再現率0%、費用5,000です。まずこの基準を記録します。
  2. τ=2.5は正解率97.88%で良く見えますが、故障149件を見逃します。τ=1.5は正解率が低くても費用は2,351と小さくなります。
  3. −1から4を0.05刻みで探索すると、この検証標本の最小費用閾値は1.5です。選択に使った標本で最終性能まで主張すると選択バイアスが生じます。
  4. 選んだ閾値を固定し、独立したテストで費用、適合率、再現率を確認します。運用時に故障率や費用が変われば、同じ閾値が適切か再検討します。
FN費用が25から100に増えたら閾値をどちらに動かしたいですか？

故障を見逃す費用が増えるため、まず警報を多く許容する低い閾値を検討します。新しい費用で検証費用曲線を再計算し、値を決めます。
