01 / 예측 시점부터 정하기

가상의 자전거 대여소에서 다음 한 시간의 대여량을 예측한다고 하자. 모델을 고르기 전에 먼저 “언제, 무엇을 알고 있는가?”를 정해야 한다. 오전 8시에 예측한다면 9시의 실제 날씨와 다음 한 시간의 반납량은 아직 모른다. 학습 데이터에 값이 있다는 이유만으로 입력에 넣으면 미래 정보가 섞인다.

이 자료는 실제 운영 자료를 사용하지 않는다. 작은 합성 예제를 통해 데이터 표현, 학습, 검증의 구조를 살펴본다. 실험 결과는 합성 조건에서의 관찰이며 실제 서비스 성능으로 해석하지 않는다.

이 장의 목표

표본과 특징의 축, 파라미터와 하이퍼파라미터를 구분한다. 예측 시점에 사용할 수 있는 입력만으로 평가 계획을 세운다.

02 / 관측을 벡터로

관측 하나를 벡터 x로 묶고 관측 여러 개를 행렬 X의 행에 쌓는다. 표본 수 N, 특징 수 D에 대해 X는 N × D 행렬이다. 목표값 y는 행마다 대응한다. 행의 순서를 바꾸면 목표값의 순서도 함께 바꿔야 한다.

핵심 식x = [기온, 예보 강수확률, 사용 가능 자전거 수]T
X ∈ ℝN×D,   y ∈ ℝN
예측 시점 기온 (°C) 강수확률 가용 대수 이후 대여량
08:00 18 0.2 24 11
09:00 20 0.1 17 14
10:00 22 0.1 12 10

숫자로 저장했다고 거리가 의미 있는 것은 아니다. 대여소 번호 1과 2가 1과 9보다 비슷하다고 볼 수 없다. 범주형 변수에는 원핫 인코딩 등 별도의 표현이 필요하다. 시간은 순환하므로 자정 전후가 가까워지도록 두 좌표로 나타낼 수도 있다.

03 / 모델은 가정을 담은 함수

모델은 입력을 출력으로 바꾸는 함수다. 선형 모델은 특징별 기여를 더한다는 가정을 담는다. 확률 모델은 같은 입력에서도 출력이 달라질 수 있다는 불확실성까지 표현한다. 어느 표현도 현실을 완전히 담지는 못한다.

핵심 식ŷ = fθ(x),   또는   p(y | x, θ)

θ는 데이터로 추정하는 파라미터다. 다항식 차수, 학습률, 정규화 강도는 학습 과정을 정하는 하이퍼파라미터다. 학습은 정해진 함수 집합 안에서 목적함수를 기준으로 파라미터를 선택하는 과정이다.

학습 형태 주어지는 것 질문
지도학습 입력과 목표값 얼마나 대여될까? 어떤 범주일까?
비지도학습 주로 입력 관측 어떤 구조·분포·압축 표현이 있을까?
강화학습 행동 이후의 상태와 보상 장기 보상을 높이는 행동은 무엇일까?

차원 축소와 군집 분석은 비지도학습의 대표 예다. 이 사이트의 실험은 지도·비지도학습에 집중한다. 강화학습은 환경과 순차 의사결정이 추가되므로 여기서는 개요만 다룬다.

04 / 좋은 예측의 기준 만들기

정답과 예측의 차이를 손실로 수량화한다. 회귀에서 제곱오차는 큰 잔차를 더 강하게 반영하고, 절대오차는 잔차 크기에 선형으로 반응한다. 손실 선택은 실수의 비용이 어떻게 발생하는지에 달려 있다.

핵심 식MSE = (1/N) Σi (yi − ŷi)²
MAE = (1/N) Σi |yi − ŷi|

잔차가 [1, −2, 3]이면 MSE는 14/3, MAE는 2다. MSE의 단위는 목표값 단위의 제곱이며, 제곱근을 취한 RMSE는 원래 단위로 돌아온다. 분류에서는 정확도 하나가 드문 클래스의 실패를 가릴 수 있어 혼동행렬도 함께 본다.

비교의 출발점

훈련 목표값의 평균만 예측하는 기준 모델을 둔다. 복잡한 모델과 단순한 기준을 같은 평가 데이터에서 비교한다.

05 / 학습과 평가 사이에 경계 두기

훈련 데이터로 계수를 구하고, 검증 데이터로 설정을 고르고, 선택이 끝난 뒤 별도의 테스트 데이터로 최종 성능을 확인한다. 테스트 결과를 보고 계속 수정하면 테스트도 사실상 검증 데이터가 된다.

대여량처럼 시간 순서가 중요하면 과거로 학습하고 이후 구간으로 검증한다. 무작위 분할은 미래 패턴을 과거 예측에 흘려보낼 수 있다. 평균·표준편차·결측치 대체 값도 훈련 구간에서만 계산한다. 독립적인 표본에서는 교차검증으로 여러 분할의 성능 변동을 확인할 수 있다.

import numpy as np
X = np.array([[18,.2,24],[20,.1,17],[22,.1,12],
              [17,.6,30],[16,.8,28],[19,.3,21]], dtype=float)
y = np.array([11,14,10,6,4,9], dtype=float)
cut = 4  # 설명용 시간 분할. 실제 성능 판단에는 표본이 부족하다.
mu, scale = X[:cut].mean(0), X[:cut].std(0)
scale[scale == 0] = 1
X_valid = (X[cut:] - mu) / scale
baseline = np.full(len(y[cut:]), y[:cut].mean())
print("validation MSE:", np.mean((y[cut:] - baseline)**2))
실험실의 평가 이름

슬라이더로 반복 비교하는 수치는 검증 오차다. 최종 서비스 성능이나 테스트 성능이라고 부르지 않는다.

06 / 이해 확인

특징 수보다 표본 수가 많으면 반드시 좋은 모델인가?

아니다. 표본의 다양성, 입력 정보, 누출, 분포 변화와 모델 가정도 중요하다. 표본 수만으로 일반화 성능을 보장할 수 없다.

전체 데이터로 표준화한 뒤 분할해도 되는가?

평가를 위한 분할에서는 훈련 구간으로 평균과 표준편차를 추정해야 한다. 전체 데이터는 평가 구간의 분포 정보를 포함한다.

학습 정리: 모델 선택보다 먼저 관측 단위, 예측 시점, 평가 기준을 정한다. 다음 장에서는 손실을 최소화하는 선형 모델을 계산한다.

심화 A / 시간 특징을 설계하고 미래를 평가하기

심화 A · 특징 설계와 분포 변화

풀어볼 문제 시간을 그대로 숫자로 넣은 모델과 주기 특징을 넣은 모델을 비교하자. 과거를 잘 설명하는 모델이 다음 시간대에도 유효할까?

가상 장비의 시간당 요청량 200개를 만든다. t=0,…,199, h=t mod 24이며 y=30+8sin(2πh/24)+6·1[t≥140]+ε, ε~N(0,1.5²)다. 요청량은 연속 근사값이며 반올림하지 않는다. NumPy 시드 2101을 사용한다. 훈련 0~119, 검증 120~159, 테스트 160~199로 고정한다.

핵심 식φ(h) = [1, sin(2πh/24), cos(2πh/24)]
θ̂ = argminθ ‖ytrain − Φtrainθ‖²
  1. 선형 시간 특징 [1,h]는 23시와 0시를 멀리 둔다. sin·cos의 두 좌표는 하루를 원 위에 놓아 자정 양쪽도 이웃으로 표현한다.
  2. 두 모델 모두 훈련 120개만으로 최소제곱을 푼다. 검증 구간을 보며 계수를 다시 맞추지 않는다.
  3. 검증 MSE는 원시 시간 특징 35.405 → 주기 특징 20.596다. 개선되었지만 생성 잡음 분산 2.25보다 훨씬 크다.
  4. t=140에서 평균이 6만큼 이동했다. 주기 모델도 이 변화를 배우지 못해 테스트 MSE가 34.592다. 표현 개선과 분포 변화 대응은 별개의 문제다.
추세 t를 특징에 추가하면 이 변화가 자동으로 해결될까?

훈련에는 급격한 수준 변화가 한 번도 없으므로 단순 추세 추가만으로 미래의 점프를 알 수 없다. 운영 중 재학습 규칙, 변화를 감지할 지표, 감지 후 성능을 별도의 시간 구간에서 평가해야 한다.

심화 B / 너무 좋은 결과에서 누출 찾기

심화 B · 잘못된 성능 진단

풀어볼 문제 MSE가 0.001보다 작은 모델이 생겼다. 뛰어난 모델일까, 예측 시점에 알 수 없는 정보가 들어갔을까?

같은 표본에서 세 가지 실수를 분리해 본다. 시간 구간을 섞는 평가, 테스트를 보며 모델을 고르는 평가, 정답의 일부를 특징에 넣는 평가는 서로 다르다. 마지막 경우를 의도적으로 재현하기 위해 “요청이 끝난 뒤 집계한 수치” z=y+δ, δ~N(0,0.02²)를 만든다. 이 특징은 예측 시점에는 존재하지 않는다.

  1. 올바른 입력 목록을 예측 시점 기준으로 작성한다. 이전 시각의 집계는 사용할 수 있지만 아직 끝나지 않은 요청의 사후 집계는 사용할 수 없다.
  2. 처음 160개를 섞어 120/40으로 나누면 주기 모델의 검증 MSE는 3.494다. 시간 순서 검증 20.596와 비교하면 분포 이동에 대한 난이도가 달라졌음을 알 수 있다. 두 검증은 관측이 다르므로 순수 모델 개선 비교가 아니다.
  3. 훈련 특징에 z를 추가하면 미래 검증 MSE도 0.000496까지 내려간다. 그러나 검증 특징 자체에 정답이 들어 있으므로 유효한 예측 성능이 아니다.
  4. 평균·표준편차·결측치 대체·특징 선택도 훈련 관측에서만 정한다. 검증에는 이미 정한 변환을 적용하고, 최종 테스트는 선택을 마친 뒤 한 번 확인한다.

train = np.arange(120)
valid = np.arange(120, 160)
mu, sd = X[train].mean(0), X[train].std(0)
sd = np.where(sd == 0, 1, sd)  # 상수 특징 처리
Z_train = (X[train] - mu) / sd
Z_valid = (X[valid] - mu) / sd
# 금지된 비교의 입력: z = y + noise
# 정답을 포함한 특징은 위 변환으로 누출이 해결되지 않는다.
훈련과 검증을 먼저 나눈 뒤 각각 정답 기반 특징을 만들면 안전할까?

아니다. 행이 겹치지 않아도 예측 시점에 모르는 정답을 입력으로 사용하면 타깃 누출이다. 행 분리와 특징의 시간적 가용성을 모두 확인해야 한다.

심화 C / 정확도 대신 비용으로 임계값 선택하기

심화 C · 불균형 분류와 비용

풀어볼 문제 고장 비율 2%인 장비에서 정확도가 높은 임계값을 선택하면 놓치는 고장도 줄어들까?

10,000개의 별도 합성 검증 관측 중 고장 200개, 정상 9,800개를 둔다. 점수는 s=2y+ε, y∈{0,1}, ε~N(0,1)이다. s≥τ이면 경보한다. 이 s는 확률이 아니므로 0.5라는 임계값에 특별한 확률적 의미가 없다. 놓친 고장(FN) 비용은 25, 오경보(FP) 비용은 1로 가정한다.

핵심 식Precision = TP/(TP+FP),   Recall = TP/(TP+FN)
Cost(τ) = 25·FN(τ) + FP(τ)
τ TP / FP / FN 정확도 정밀도 / 재현율 총비용
0.5 191 / 3003 / 9 69.9% 6.0% / 95.5% 3228
1.5 133 / 676 / 67 92.6% 16.4% / 66.5% 2351
2.5 51 / 63 / 149 97.9% 44.7% / 25.5% 3788
  1. 모든 관측을 정상이라고 하면 정확도는 98%지만 고장 재현율은 0%, 비용은 5,000이다. 이 기준선부터 기록한다.
  2. τ=2.5는 정확도 97.88%로 좋아 보이지만 고장 149개를 놓친다. τ=1.5의 정확도는 더 낮아도 비용은 2,351로 작다.
  3. −1~4를 간격 0.05로 탐색하면 이 검증 표본의 최소 비용 임계값은 1.5다. 이 값을 고른 표본으로 최종 성능까지 주장하면 선택 편향이 생긴다.
  4. 선택한 임계값을 고정하고 독립 테스트에서 비용·정밀도·재현율을 확인한다. 운영에서 고장 비율이나 비용이 바뀌면 같은 임계값이 적절한지 다시 검토한다.
FN 비용이 25에서 100으로 늘면 임계값을 어느 방향으로 움직이고 싶은가?

고장을 놓치는 비용이 커지므로 더 많은 경보를 허용하는 낮은 임계값 쪽을 우선 검토한다. 정확한 값은 새 비용으로 검증 비용 곡선을 다시 계산해 결정한다.
