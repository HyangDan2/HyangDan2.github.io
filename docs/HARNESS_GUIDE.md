# Web-HQ Harness Guide

상태: **현재 저장소에서 확인한 절차와 Phase 2 제안을 구분한 운영 가이드**. 이 문서는 Web-HQ 자체를 다룹니다. 교육 사이트 EDPilot0001의 작성·빌드 절차는 [교육자료 작성 가이드](education-harness-guide.md)를 따릅니다. 다중 허브 차세대 설계는 [`platform-architecture/phase1/`](platform-architecture/phase1/)의 문서 7개를 참조합니다. 설계 문서는 구현·배포 완료의 증거가 아닙니다.

## 1. 소유 범위와 불변 조건

Web-HQ는 `https://hyangdan2.github.io/`의 진입 화면, EduHub·GameHub·TechnicalHub로 가는 링크, `analysis.html`의 연구 목록과 `analysis/<key>/` 정적 대시보드를 소유합니다. 각 허브, 교육 사이트, 게임 및 기술 프로젝트는 자신의 저장소와 배포를 소유합니다. Web-HQ 변경을 위해 다른 프로젝트의 빌드·배포를 묶지 않습니다.

- 기존 루트 URL, `analysis.html`, `analysis/<key>/<key>.html`, 세 허브 링크, 분석 페이지의 뒤로 가기·테마·언어 동작을 보존합니다.
- 현재 사이트의 CSS·레이아웃·문구를 의도하지 않게 바꾸지 않습니다. 차세대 공통 내비게이션은 링크와 동작 규약을 공유하고, 화면 스타일은 Web-HQ가 유지합니다.
- 공개 저장소와 GitHub Pages에 들어가는 파일은 공개 자료로 취급합니다. 비공개 프로젝트의 소스, 내부 경로, 토큰, 미승인 설명·이미지를 넣지 않습니다.
- 분석의 수치·주장·출처는 해당 자료의 근거로 검토합니다. 생성된 값이나 조사일을 추측하여 채우지 않습니다.

## 2. 현재 파일과 데이터 흐름

| 파일 | 역할 | 변경 시 확인할 것 |
| --- | --- | --- |
| `index.html`, `style.css`, `script.js` | HQ 진입 화면, 세 허브 카드, About 대화상자 | 링크 대상, 키보드 조작, 대화상자 닫기·초점, 데스크톱·모바일 표시 |
| `analysis.html`, `analysis-index.css`, `analysis-index.js` | 분석 목록, 검색·필터·정렬·테마 | 목록의 여섯 항목, 필터 결과, 데이터 오류 상태, 상세 링크 |
| `analysis/manifest.json` | 공개 분석 목록의 원본 | 고유 `key`, 기존 URL, 대상 파일·`latest_json` 참조 |
| `analysis/<key>/<key>.html/.css/.js` | 개별 정적 대시보드 | 직접 접속, 목록·HQ 복귀, CSS/JS, 차트, 언어·테마 |
| `analysis/<key>/latest.json` 및 `raw_data/*.json` | 브라우저가 읽는 공개 분석 데이터 | JSON 파싱, 실제 파일 존재, 경로 범위, 출처·공개 가능성 |
| `analysis/docs/About_Generating_Update_Program_Rule.md` | 분석 데이터 생성·갱신 규칙 | 생성 절차가 바뀔 때 함께 검토 |

현재 `analysis-index.js`는 manifest를 받은 다음 각 `latest.json`과 원천 JSON을 브라우저에서 읽습니다. 원천 JSON은 현재 사이트 동작에 필요한 공개 파일입니다. Global Registry에는 이 데이터 전체를 복제하지 않고, 검토된 목록 메타데이터만 내보내는 것이 차세대 설계입니다.

2026-10-27 Web-HQ 홈은 Server HQ의 시각적 구성에 맞춰 헤더, 좌우형 히어로, 전용 SVG 일러스트, 동일 색상의 3열 허브 카드와 간결한 푸터로 갱신했습니다. 이 디자인 변경은 Web-HQ 홈에만 적용합니다. `analysis.html`과 다른 허브 사이트의 디자인은 이 변경 범위에 포함되지 않습니다. 홈 일러스트 원본은 `assets/hq-hero.svg`이며 외부 런타임 이미지 의존성이 없습니다.

## 3. 현재 실행 가능한 로컬 확인

저장소 루트에서 다음 명령으로 정적 서버를 시작합니다. `file://`로 열면 `fetch()` 동작이 달라지므로 서버를 사용합니다.

```sh
python3 -m http.server 8000
```

`http://localhost:8000/`, `/analysis.html`, manifest에 나열된 각 상세 URL을 브라우저에서 확인합니다. JSON 문법만 빠르게 확인하려면 `python3 -m json.tool analysis/manifest.json >/dev/null`을 사용할 수 있습니다. 각 `latest.json`과 대상 raw JSON도 같은 방식으로 확인합니다. 이 명령은 **문법 검사일 뿐** 링크·내용·공개 경계를 검증하지 않습니다.

현재 Web-HQ에는 `package.json`, 프로젝트 빌드 명령, 자동 브라우저 테스트, `.github/workflows`가 없습니다. 따라서 `npm run verify` 같은 명령이나 CI 통과를 현재의 절차로 보고하지 않습니다. GitHub Pages 게시 소스와 실제 호스팅 상태도 저장소 파일만으로 단정하지 않습니다.

## 4. 변경별 수동 점검

### HQ 화면 또는 내비게이션

1. 세 허브 카드와 현재 GitHub 링크의 목적지가 의도대로 유지되는지 확인합니다. 링크 수정은 별도 변경으로 기록합니다.
2. About 버튼을 키보드로 열고 닫으며 닫힌 후 초점이 버튼으로 돌아오는지 확인합니다. 배경 클릭과 Escape도 점검합니다.
3. 1440px와 좁은 모바일 폭에서 텍스트, 카드, 초점 표시, 확대 시 가로 넘침을 확인합니다. 변경 전후 화면을 비교합니다.
4. 세 허브 카드가 동일한 배경색·테두리·강조색을 사용하는지 확인합니다. 새 히어로 일러스트가 로드되고 데스크톱 좌우 배치와 모바일 세로 배치에서 텍스트를 가리지 않는지 확인합니다.

### 분석 목록 또는 데이터

1. `analysis/manifest.json`의 `key`가 중복되지 않고 각 `url`·`latest_json`이 저장소 안의 실제 파일을 가리키는지 확인합니다. 대소문자를 포함한 기존 URL을 그대로 유지합니다.
2. 각 `latest.json`의 `latest` 값이 해당 분석 폴더 안의 의도한 `raw_data/*.json`을 가리키는지 확인합니다. 절대 경로, `..` 경로 이탈, 외부 URL, 심볼릭 링크를 허용하지 않습니다.
3. 분석 목록에서 검색, 자산 유형·시장 필터, 정렬, 테마 전환, 카드 클릭과 빈 결과 상태를 확인합니다.
4. 여섯 상세 페이지를 각각 직접 열고 새로고침합니다. 데이터 로드, 차트 표시, 언어·테마 전환, 목록·HQ 복귀 링크를 확인합니다. 현재 차트는 외부 CDN 스크립트를 사용하므로 해당 네트워크 장애는 별도로 기록합니다.
5. raw JSON의 수치·출처·서술을 공개 자료로 검토합니다. HTML·JS가 JSON 값을 `innerHTML`에 삽입하는 지점이 있으므로 외부 또는 생성 데이터의 HTML 실행 가능성을 보안 검토 항목으로 둡니다. 현재 코드가 이 위험을 모두 막는다고 가정하지 않습니다.

### 공개 경계

변경 파일과 게시될 파일 목록을 검토합니다. 자격 증명, 개인 로컬 경로, 비공개 저장소 URL, 내부 증거, 미승인 이미지·도표가 없는지 확인합니다. 의도적으로 공개 중인 분석 raw JSON은 삭제 대상으로 일괄 분류하지 않고, 각 파일의 공개 적합성을 검토합니다.

## 5. 차세대 Phase 2 작업을 시작할 때

별도 승인 후 [`IMPLEMENTATION_WORK_ORDER.md`](platform-architecture/phase1/IMPLEMENTATION_WORK_ORDER.md)의 순서를 따릅니다. 먼저 현재 호스팅 URL·화면·게시 설정을 기준선으로 남깁니다. 그 다음 Web-HQ만을 위한 깨끗한 정적 산출물, manifest 변환 어댑터, 공개 `data/projects.v1.json`, 자동 검증·산출물 감사, 독립 Pages workflow를 **제안된 기능**으로 구현합니다. 원본 분석 파일과 공개 URL은 유지합니다. Web-HQ 배포는 다른 허브나 Global Registry의 성공을 기다리지 않습니다.

예정된 자동 검증은 manifest/`latest.json` 경로와 중복 검사, URL 회귀, 브라우저 동작, 공개 산출물 내용 검사로 구성합니다. 구현되기 전에는 명령 이름을 이 가이드의 현재 실행 절차에 추가하지 않습니다. 새 프로젝트 등록은 승인된 메타데이터 변경만으로 처리하고 HQ 화면 코드에 프로젝트별 분기를 추가하지 않는 것이 목표입니다.

## 6. 게시·복구·완료 보고

게시 전에는 실제 GitHub Pages 소스 설정과 배포 절차를 확인하고 검증 결과를 기록합니다. 이 가이드는 확인되지 않은 Actions workflow나 게시 성공을 주장하지 않습니다. 구현 후에는 해당 저장소의 정상 산출물만 게시하고 루트·분석 목록·여섯 상세 경로를 공개 URL에서 다시 확인합니다. 오류가 나면 해당 변경을 되돌려 Web-HQ의 마지막 정상 상태를 복원하며, 다른 허브 배포는 계속할 수 있어야 합니다.

완료 보고에는 수정 파일, 확인한 원본 데이터, 실제 수행한 로컬·브라우저·호스팅 검사, 저장소 revision, 배포 URL과 미검증 항목을 구분해 적습니다. 문서 절차와 실제 도구가 달라졌다면 같은 변경에서 이 가이드를 갱신합니다.
